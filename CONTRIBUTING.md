# Contributing

## Development environment

A devcontainer is provided and is the least surprising way to work on this
provider: it pins the Go and tool versions, joins the container to the
acceptance-test network so the backend is reachable as `http://backend:8000`,
and pre-configures `dev_overrides` so the examples run against the locally
built binary without `terraform init`.

Working outside the devcontainer needs Go 1.25, Terraform, Docker and
`make tools`.

Note that the repository sets `GOWORK=off` in the Makefile and CI: the
provider is a standalone module and must not be absorbed into an unrelated
`go.work` further up the directory tree.

## The containerized SecObserve

`test/docker-compose.yml` runs the published backend image and a PostgreSQL
database — no Traefik, no frontend, since a provider test needs neither.

```console
make up                        # start it and mint a superuser API token
eval "$(./test/bootstrap.sh)"  # export SECOBSERVE_BASE_URL / _API_TOKEN
make down                      # stop it and delete the volumes
```

`make down` deletes the volumes on purpose. SecObserve performs its SPDX and
ScanCode license import on first start, and the license tests depend on that
state being pristine.

For the OIDC tests, `make up-oidc` adds Keycloak with the realm vendored from
upstream (realm `secobserve`, public client `secobserve`, user
`keycloak_user` / `keycloak` in group `keycloak-group`). `KC_HOSTNAME` is
pinned so the token's `iss` claim matches the backend's `OIDC_AUTHORITY`, which
means tokens must be fetched over the compose network — run these tests from
the devcontainer or CI, not a bare host shell.

## The vendored API schema

`api/openapi.json` is the contract with SecObserve. It is fetched from a
running instance rather than written by hand:

```console
make up
eval "$(./test/bootstrap.sh)"
make schema      # refetch api/openapi.json
make generate    # regenerate api/models.gen.go
```

CI fails when the committed schema and generated code are stale, so bumping
the target SecObserve version is always a reviewable commit. Bumping means:
change `SECOBSERVE_VERSION` in `test/.env` and `client.SchemaVersion` in
`internal/client/status.go`, then rerun the two commands above.

Only models are generated. The transport layer in `internal/client` is
hand-written because the generated client cannot express SecObserve's
`APIToken` scheme, its page-number pagination or the delete-confirmation query
parameters.

## Tests

```console
make test        # unit tests, no SecObserve needed
make testacc     # acceptance tests against the containerized instance
make testacc-oidc
```

Every resource must have an acceptance test that **applies twice and asserts
the second plan is empty**. This is not boilerplate: SecObserve silently
rewrites submitted values in a dozen places (see
`docs/design/api-quirks.md`), and a plain create/read test does not catch it.
Use `plancheck.ExpectEmptyPlan()` in a post-apply `ConfigPlanChecks`.

Two further rules that follow from the same section:

- Always write resource state from the API response body, never from the plan.
- Attributes the server may fill in or clear must be `Optional + Computed`.

## Documentation

`docs/` is generated by `tfplugindocs` from the schema descriptions,
`templates/` and `examples/`:

```console
make docs
```

`tfplugindocs` owns `docs/index.md`, `docs/resources/` and
`docs/data-sources/`. `docs/design/` is hand-written and is not part of the
registry documentation.

Write attribute descriptions as `MarkdownDescription`, and mention any
SecObserve behaviour the user cannot infer — an immutable field, a value that
is never returned, an approval step that happens out of band.

## Code style

Comments explain *why*, in one line, and point at
`docs/design/api-quirks.md` rather than restating it. `make fmt` and
`make lint` before pushing.
